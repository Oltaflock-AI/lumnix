Request / Auth Flow

Client uses apiFetch() which attaches the Supabase session JWT as a Bearer token. All /api/* routes are gated by src/middleware.ts: it validates the JWT via supabase.auth.getUser(), checks workspace_members membership for any workspace_id in the query/body, then injects a trusted x-user-id header (stripping any client-supplied one) for the route handler. Cron routes bypass user auth and validate CRON_SECRET instead. Public routes are allow-listed.

Medium Priority

MediumM1

Route-level workspace authorization is inconsistent (defense-in-depth)

Fixed
Evidence
Several GET/POST routes read workspace_id and rely only on middleware — no route-level verifyWorkspaceAccess(): api/anomalies, api/insights, api/briefings, api/alerts (GET+POST; PATCH/DELETE are guarded), api/reports/generate, api/billing/*.
Risk
Mitigated today (middleware validates workspace_members membership for query & body workspace_id). But it's brittle: any middleware bypass or a route reached by a non-standard path is unguarded. Billing routes also don't check billing role, only membership/owner.
Fix
Add verifyWorkspaceAccess(req, workspaceId) at the top of each listed handler for defense-in-depth.
